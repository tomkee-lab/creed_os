# WAY 2.1 Editorial Artwork & Taxonomy

## 1. Emotional Function
Artwork in CREED OS carries emotion and establishes context.
UI components carry information and prompt action.
Artwork should never compete with operational interfaces or serve as decorative filler.

---

## 2. Role-Based Imagery Allocation
- **Landing Page:** 1 Hero narrative artwork (`hero_observatory.jpg`).
- **Student Home:** 1 Active maker studio artwork (`student_workshop.jpg`).
- **Pathways:** 1 Primary domain artwork per field (`pathway_robotics.jpg`, `pathway_bio.jpg`).
- **Parent Portal:** 1 Shared horizon family dialogue artwork (`parent_horizon.jpg`).
- **Teacher Copilot:** Minimal/no illustration. Data and action-first interfaces.
- **Counselor Center:** Minimal/no illustration. Structured case management.
- **Admin Console:** None.
- **Item Studio:** None (only scientific curves and data visualizations).

---

## 3. Strict Taxonomy Rule
Never reuse the same illustration across unrelated fields or disciplines:
- **Engineering / Robotics:** Kinematic mechanisms, articulated arms, circuit blueprints.
- **Life Sciences:** Botanical biomimicry, cellular specimens, natural field research.
- **Physical Sciences:** Optical instruments, balance scales, laboratory kinematics.
- **Creative Technology:** 3D structural simulations, spatial modeling.
